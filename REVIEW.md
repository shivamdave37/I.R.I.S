## What the files do

- `config.py` lists approved websites, app paths, and future-stage settings.
- `router.py` normalizes typed input and routes approved commands.
- `main.py` reads commands in the configured mode, prints replies, speaks them in voice modes, and records command results when logging is available.
- `voice.py` listens for a short spoken command and queues spoken replies through one dedicated speaker thread.
- `skills/web.py` opens a configured website.
- `skills/apps.py` checks an approved app path and starts it without a shell.
- `skills/timeinfo.py` returns the current local time and date.
- `tests/test_router.py` checks routing, formatting, refusal of unknown apps, and loop behavior without opening real apps or sites.
- `tests/test_voice.py` checks timeout/error handling, queued speech, shutdown, and typed fallback without using audio hardware.
- `README.md` explains setup, commands, tests, and app path configuration.
- `.gitignore` keeps secrets, virtual environments, generated bytecode, data, and logs out of Git.
- `.env.example` is a placeholder for the later AI stage; it contains no real key.
- `requirements.txt` lists SpeechRecognition, pyttsx3, and PyAudio for voice input and output.
- `AGENTS.md`, `HANDOFF.md`, `PROMPTS.md`, and `SPEC.md` contain the collaboration rules, current turn, stage prompts, and project requirements.

## Run and test

- Install packages in the activated project virtual environment: `python -m pip install -r requirements.txt`
- Start: `python main.py`
- Test: `python -m unittest discover tests`

See `README.md` for setup details and the available commands.

## Known problems and human checks

- VS Code and Codex paths in `config.py` are placeholders and must be edited before those apps can open.
- YouTube, Google, GitHub, Chrome, and Notepad commands returned successful open responses during the owner's authorized Stage 1 command check.
- Microphone recognition and speech output require a human test on the owner's audio hardware.
- The `.env.example` is not used in Stage 2.

## Errors and handling

- Browser and app launch exceptions return a friendly reply instead of stopping the command loop.
- If the log directory or file cannot be written, Jarvis continues without logging.
- Unit tests mock browser and app launching; they do not verify the owner's installed apps or default browser.
- Unit tests mock microphone and speaker behavior; they do not verify the owner's microphone, internet recognition, or Windows speech output.

## Reviewer findings

- **Whitespace collapsing**: Commands with extra spaces between words (such as `"what's   the   time"` or `"open   youtube"`) previously failed to match because `router.normalize()` preserved internal multi-spaces. Updated `router.normalize()` to collapse multi-spaces, adhering strictly to SPEC.md section 4.
- **Punctuation-only input**: Punctuation-only inputs (like `"???"` or `"!"`) were reduced to `""`, causing `router.handle()` to return an empty string and Jarvis to print an empty line (`Jarvis: `). Fixed to return the fallback response `"I don't know that yet."` for any unrecognized non-empty input.
- **Safe empty/None handling**: `router.normalize(None)`, `router.handle(None)`, and `router.is_exit_command(None)` previously raised `AttributeError`. Added safeguards returning `""` and `False` safely without crashing.
- **Browser launch failure check**: `webbrowser.open()` returns `False` if browser launching fails. `skills/web.py` now checks for `False` and returns a friendly error message instead of falsely reporting success.
- **Windows log encoding**: Added `encoding="utf-8"` to `logging.basicConfig()` in `main.py` to prevent potential `UnicodeEncodeError` on Windows when recording non-ASCII commands.
- **Documentation & WHY-comments**: Added missing "why" comments to functions across `router.py`, `main.py`, and `skills/` to satisfy AGENTS.md rule 10.
- **Unit test suite expansion**: Added 8 new unit tests in `tests/test_router.py` covering multi-space commands, punctuation-only fallback, None-safety, browser failure handling, placeholder/missing app checks, launch exceptions, and logging execution (16 tests total, all passing).
